## What this is

A living, machine-assisted **visual architecture system** for the Zentro platform. It has four parts:

1. **Human-readable docs** (this folder) — high-level maps, domain boundaries, coupling risks,
   written by humans, kept stable.
2. **A machine-readable graph** — [`docs/architecture/graph/zentro-graph.json`](graph/zentro-graph.json)
   with typed `nodes` + `edges`. This is the single source of truth that can power an
   interactive React Flow viewer (`/dev/architecture`) — no manual diagram editing.
3. **AUTO-GENERATED FACTS** — `docs/architecture/graph/zentro-graph.json` is meant to be
   regenerated by [`scripts/architecture/`](../../scripts/architecture/) so code and docs never drift.
4. **HUMAN-MAINTAINED ARCHITECTURE NOTES** — the `*.md` files in this folder, which layer
   intent and risk on top of the raw facts.

> The important architectural rule: **facts vs. intent are kept separate.**
> The graph JSON contains facts (who imports whom, which model has an FK to which).
> The markdown contains intent (why a boundary exists, what to rework). If they ever disagree,
> **the graph is ground truth** and the markdown should be updated.

## Generation & keeping it current

The graph JSON is the contract for the interactive viewer. It is meant to be regenerated
from the codebase automatically. See:

- `scripts/architecture/` — scanner API (frontend TS + backend Python) with a **dry-run
  / no-package-install design**, so it runs anywhere and never installs dependencies.
- `graph/zentro-graph.json` — the current snapshot (generated facts).
- `viewer/interactive.md` — the `/dev/architecture` React Flow proposal.

> **Do not hand-edit the graph JSON.** Regenerate it with the scanner. Hand-edit the `.md`
> files when you change architecture *intent*.
